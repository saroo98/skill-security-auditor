# Security Policy

## Reporting Vulnerabilities

Report vulnerabilities through the repository's security advisory workflow when available. If advisories are not enabled, open a minimal issue asking for a maintainer contact path without posting sensitive details.

## Scope

Security reports may cover the scanner, examples, documentation that could mislead users into unsafe behavior, and CI configuration.

## Handling Sensitive Data

Do not include real credentials, tokens, customer data, private repository content, or production logs in issues or pull requests. Use sanitized samples with documentation-safe placeholders such as `example.com`, `user@example.com`, `sk-EXAMPLE-DO-NOT-USE`, and `203.0.113.20`.

## Disclosure

Give maintainers reasonable time to review and fix confirmed issues before public disclosure.
